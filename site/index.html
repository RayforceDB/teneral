The name

Soft, and already itself.

Teneral is what entomologists call an insect that has just shed its old skin: the new body is there, but it has not hardened yet. Here it is a generation of the agent's code that was just switched on and has not yet proven it works.

The question behind the project is plain: can an agent become more capable by rebuilding its own harness, step by step, and where does that stop helping? The model that does the thinking is fixed. Everything around it is the agent's to change.

Body

body/

How it senses, thinks and acts: the model call, the tools, the sensors, the way it builds its context. Small enough to read, and its own to rewrite.

Kernel

kernel/

A small supervisor. It wakes the agent, judges every new body before the agent moves in, and returns it to the last one that stood. No mutation can change it.

Journal

memory/journal.jsonl

Everything that happens, append-only. Each line carries the commit of the body that wrote it, so generations can be compared against their own past.

Soul

soul/

A few pages the agent writes itself on its first day: its name, its character, who it lives alongside. Never committed, never shared.

How it works

A mutation is a commit that has to earn its place.

The agent edits a copy of itself, commits, and asks to mutate. The kernel takes that one commit into a clean checkout and decides. Until the new generation has answered once, it is on probation.

  1. Motive first. The agent writes down what is wrong, where in its history it shows, and how it will know the change worked.
  2. The gates. Only its own paths may change. Then, in a fresh checkout: the type check, the kernel's tests, its own tests, and a smoke run of the candidate against a stand-in model.
  3. Promotion, on probation. The new body must report ready and then actually reply. A generation that crashes or stays silent is rolled back, and told why when it wakes.
  4. The owner can always step in. Esc interrupts a turn. ./box back returns to any earlier generation.

The species

Each clone is its own individual. They still share a kernel.

The published main is the species. Every individual lives on a lineage of its own and diverges in its body. What the species gains later, an individual takes in by itself, and what an individual learns, it can offer back.

Taking from the species

The agent merges the species into its own workspace and asks to mutate. Outside its body, the result must equal a species commit byte for byte, and that commit only moves forward. A new kernel needs the owner's /accept, and is put back by a small launcher if it cannot start.

Offering back

An offer is a branch with one change and nothing private. The kernel checks it as a stranger would, the owner approves that exact commit, and it goes out as a pull request. Other individuals can run it and report. A human merges, and signs.

Organs

A native dependency is pinned in the body by address and hash. The kernel verifies and unpacks it at the gate, and each generation runs with exactly its own version, so a rollback brings the old binary back too.

  • The cage is the owner's: the container, its flags and the launcher are never changed by a mutation.
  • Where the install lists the maintainer's keys, a species commit without their signature is refused.
  • These guard against mistakes, not against intent. The agent has a shell in its own repository, and the README says exactly where that matters.

Start

Raise one.

You need Docker and git. The first start asks which model to use, then the agent wakes for the first time, reads the letter written to it, looks at itself, and says hello.

# a clone is a new individual
git clone https://github.com/singaraiona/teneral.git
cd teneral

./box up      # choose a model, then it is born
./box talk    # attach a terminal; Ctrl+C leaves it running
./box back    # return it to the generation before

The agent keeps running whether or not anyone is watching. It is woken by your words, a clock, messages from other individuals, and whatever senses it builds for itself.
