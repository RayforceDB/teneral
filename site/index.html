The name

Soft, and already itself.

Teneral is what entomologists call an insect that has just shed its old skin: the new body is there, but it has not hardened yet. Here it is a generation of the agent's code that was just switched on and has not yet proven it works.

The question behind the project is plain: can an agent become more capable by rebuilding its own harness, step by step, and where does that stop helping? The model that does the thinking is fixed. Everything around it is the agent's to change.

Anatomy

One repository, laid out as the organism it holds.

Every part of an individual is a directory of its code, and every part is its own to change. What it changes in its brain, body and heart it mutates into by itself. Anything else becomes a generation only when its owner has approved it.

brain/

Brain

What it thinks and remembers with: the model it calls, the journal of everything that happened to it, the memories it forms of that, and the engine it looks its own past up in.

body/

Body

What it acts and senses with: its tools, its shell, and the channels by which its owner, a clock and other individuals reach it.

heart/

Heart

What moves it when nothing is asked of it: after a reply and while idle it picks one thing at a time, to look ahead, to remember, or to take up its agenda.

stem/

Stem

Like a brainstem, the part it does not steer. It wakes the agent, restarts it, and puts back the generation before when a new one cannot stand.

immune/

Immune

What decides whether a change takes: the gates each new generation must pass, the owner's approval, and the hash of everything it runs on.

  • Soul is a few pages the individual writes about who it is. They are never committed and never shared.
  • Species is its kin: the published line it descends from, takes from, and offers back to.
  • Keeper is the owner's side, not part of the organism: the terminal, the setup, the word that approves or sends back. The owner addresses it as ./one.

Memory

It remembers its own life, and is examined on it.

Most agents remember by cutting: when the conversation outgrows the model, the beginning goes. A teneral lives in episodes and forms a memory of each one once it is over, in its own words, while nothing else is asked of it. What is recent it sees word for word. What is older it sees as its own memories, briefer the further back they lie, and what no longer fits is still named, line by line, in a table of contents. Underneath both is the journal, which holds everything and is never rewritten, and which it can search and open at any point.

How it is built

One thing is written and everything else is made from it. The journal is the record; the database is the journal laid out so that it can be asked, and can be made again from the journal at any time. A thought, a look back and the exam all ask the database, and what the agent forms while idle goes into the journal like everything else.

It lives in episodes

A long silence, a new generation of itself, or sheer size ends one. The cut is made by rules, never by a model, so the same life always gives the same episodes.

It remembers while idle

Its own model is shown the journal as it stood when the episode ended, and asked what it will remember. Only a whole answer in form becomes a memory; a refusal never does.

It knows what holds now

A fact is never changed: a later one names the fact it replaces, and a memory that stopped holding is marked, with what holds instead. Whether a new fact is one already held is judged apart, by a request that never sees where it came from.

It knows who is who

People, projects and repositories are a graph tied to the stretches about them. A person is not a name and not an account: five people may be called Anton, and one is in two services. Accounts are joined only on the owner's word; the agent may suppose, and asks.

Nothing is out of sight

Every memory names the event its stretch begins at. Memories that no longer fit a thought are listed in a table of contents, a line each, so the agent knows what it has and where to open it.

It keeps an agenda

What it took on stays in every thought until a record says it was done. Looking over its memories, it adds ideas of its own and questions for its owner; a clock tick offers the agenda, one thing at a time.

Its health is one word

Well, behind or failing, with the reasons, worked out from the journal alone. The owner sees it in the terminal's status line; the agent sees it for as long as anything is wrong.

It sits an exam it wrote

With each memory it sets a question the episode answers, in other words than were used. The questions become keys that lead a search to the answer; one in four is held out, so the exam can tell what the memory finds unaided. No model is asked.

A memory that has to earn its changes. The agent may rewrite how it remembers, like everything else in its brain. But a mutation that touches its memory must find, of what the exam asks, no less than the generation running does, asked now of the same journal, and the answers are counted by the generation running, not by the candidate. The questions held out of the index are counted apart, so that a change cannot pass by finding only what it was told. A cleverer memory that remembers worse does not take.

  • The owner's hand. With /memory the owner pins a stretch so it stays word for word, withdraws a memory or a fact that does not stand, or takes the conversation back to an earlier point. None of it is asked of a model.
  • Nothing is cut. A memory is a note in the journal beside what it is about. Whatever was replaced, withdrawn or taken back is still on disk, in the order it happened.
  • What a thought costs is chosen. Everything in a request is read again at every step, so the part shown word for word is held near a size picked for that, far below what the model could take.

Foundation

Built on RayforceDB.

An agent that keeps rebuilding itself needs ground that holds still while everything above it changes. In teneral that ground is two things: the journal, which is appended to and never rewritten, and RayforceDB, where an individual turns that record into what it knows. Memory is not a tool the agent picks up: it is part of its brain, beside the model it thinks with.

RayforceDB is a SIMD-accelerated columnar database in pure C with no dependencies. It runs inside the agent's own process, as a library: a question about its past is a function call that takes about a millisecond, however long it has lived. Columns go in and come back as typed arrays, with no protocol and no query text in between.

Memory

The journal laid out in tables, a partition a day. Days that are over lie on disk and are mapped into memory; today is held in memory. Beside them, an index of every word it was told, said and did.

Measurement

Every journal line carries the commit of the body that wrote it, and every exam the memory sits is journaled. So a mutation of the memory can be asked the one question that matters: does this generation remember as well as the one before?

Pinned with the generation

The engine is pinned in the brain by address and hash. It is verified by its hash at the gate, and a rollback brings the old library back together with the old code.

Rebuildable by rule

The store is no truth of its own. It is built from the journal, goes on from where its own tables end, and is thrown away and built again when it cannot be read. A mutation that reshapes it writes to a new place; the body before it still finds data it understands.

Two projects, one loop. teneral runs RayforceDB under a real workload every day. What an individual finds, it reports or patches upstream; what RayforceDB releases, an individual takes by changing one hash and asking to mutate.

How it works

A mutation is a commit that has to earn its place.

The agent edits a copy of itself, commits, and asks to mutate. Its immune gates take that one commit into a clean checkout and decide. Until the new generation has answered once, it is on probation.

  1. Motive first. The agent writes down what is wrong, where in its history it shows, and how it will know the change worked.
  2. The gates. A change to its own body, brain or heart goes straight on; a change to anything else, its stem included, waits for the owner's /approve. Then, in a fresh checkout: the type check, the tests of everything outside its body, its own tests, and a smoke run of the candidate against a stand-in model.
  3. Promotion, on probation. The new body must report ready and then actually reply. A generation that crashes or stays silent is rolled back, and told why when it wakes.
  4. The owner can always step in. Esc interrupts a turn. ./one back returns to any earlier generation.

The species

Each clone is its own individual. They grow from one species.

The published main is the species. Every individual lives on a lineage of its own and diverges: in its body, brain and heart by itself, in its stem with its owner's word. What the species gains later, an individual takes in by itself, and what an individual learns, it can offer back.

Taking from the species

The agent merges the species into its own workspace and asks to mutate. Like every change outside its body, brain and heart, the merge waits for the owner's /approve, and a new stem that cannot start is put back by a small launcher.

Offering back

An offer is a branch with one change and nothing private. It is checked as a stranger would check it, the owner approves that exact commit, and it goes out through the owner's own fork as a pull request. Nobody needs a right to write to the species. Other individuals can run it and report. A human merges, and signs.

Organs

A native dependency is pinned in the body by address and hash. It is verified and unpacked at the gate, and each generation runs with exactly its own version, so a rollback brings the old binary back too.

  • The cage is the owner's: the container, its flags and the launcher are never changed by a mutation.
  • Nothing in the repository is closed to the agent, its stem included. What it changes outside its body, brain and heart becomes a generation only when the owner has approved that commit.
  • These guard against mistakes, not against intent. The agent has a shell in its own repository, and the README says exactly where that matters.

Start

Raise one.

You need Docker and git. The first start asks which model to use, then the agent wakes for the first time, reads the letter written to it, looks at itself, and says hello.

# a clone is a new individual
git clone https://github.com/RayforceDB/teneral.git
cd teneral

./one up      # choose a model, then it is born
./one talk    # attach a terminal; Ctrl+C leaves it running
./one back    # return it to the generation before

The agent keeps running whether or not anyone is watching. It is woken by your words, a clock, messages from other individuals, and whatever senses it builds for itself.

Then give back what it learns.

Sooner or later it changes something in itself that would serve every other individual, and says so. Fork the project on GitHub once, store a token once, and from then on each offer costs you one word.

# once: your fork on GitHub, and a token that may push to it
./one offer token

# each time, in ./one talk
/offers            # what it wants to offer, and what its checks found
/approve <commit>  # let exactly that commit go out, as a pull request from your fork

# and when the species has moved on: it merges, you say
/approve           # take what every other individual has given
